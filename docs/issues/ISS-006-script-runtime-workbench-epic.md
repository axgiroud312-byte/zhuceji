# ISS-006：将现有工具转为通用注册脚本运行管理台（总目标）

## 目标与范围

产品是通用注册框架的可视化运行管理台。网站脚本由 AI 在外部编写，导入后使用；脚本决定如何注册、获取什么结果。框架提供邮箱、动态代理、调度、状态、日志、保存与导出。通用性来自脚本与框架的分工。

用户已确认（2026-10-19）：
- 邮箱资源和动态代理池在设置中配置、长期保存，可供不同网站脚本复用；主页显示资源摘要与选择入口。
- 主页选择资源、选择对应网站脚本、填写数量、启动、查看和导出结果。
- 填 20 就创建并执行 20 个任务，不为失败任务自动补数量；失败记录原因。
- 脚本导入一次后长期保存在列表中，可重复选择、更新。
- 第一版沿用用户此前注册 Agnes 的邮箱资源和收信方式；具体实际接入由代码调查确认，不要求用户重新提供已有资料。
- 结果字段由脚本定义，工作台按声明展示、保存、导出，不固定为 API Key。
- 同一时间只允许运行一个网站。
- 界面现代、交互简单、任务日志清晰。任务结果是主工作区，日志可按任务查看，技术详情按需展开。
- 不提供流程制作、录制、节点编辑或选择器编辑，也不把这些功能藏入高级设置。

本轮包含脚本接入、资源绑定、运行语义、结果通用化、主页调整及原有数据兼容。保留本地 Web 启动方式与现有凭证保护能力；不增加远程托管或账号系统。

## 必要设计与依据

现有 `domain.py` 的 Adapter、`scheduler.py`、`mailbox.py`、`proxy.py` 和持久化能力是复用起点。`web.py`、`web_ui.py` 当前围绕 Agnes 流程配置，`models.py` 有固定 `api_key_ref`，必须核对并拆除平台假设，不能仅改页面文案。

与旧需求冲突时以本 Issue 为准。ISS-000～005 保留为历史交付记录，流程编辑与固定 Agnes 品牌/DOM 的旧验收不再约束新产品；不以旧测试通过代表新需求完成。

### 实施建议与待调查（不冒充用户确认）
- 建议同网站支持任务并发；并发默认值、停止时的收尾方式由 ISS-010 核对现有能力后记录。
- “不补数量”不自动等于允许任务内重复注册：需明确网络重试与重新注册的边界，避免隐式补跑。
- 建议历史任务自动保存；迁移和脚本更新不得让已有记录失去解释依据。
- 上方资源/脚本/运行控制、中部结果列表、底部日志为讨论中的布局方向，具体视觉尚未验收。
- 脚本包格式、接口版本、依赖支持范围、资源分配与跨网站复用规则由相应子任务调查并形成可执行约定。

## 验收方法

从设置保存资源开始，完成导入脚本、主页选择资源/脚本、运行固定数量、按任务看日志、查看并导出脚本结果的闭环。
用 Agnes 适配和一个输出不同字段的本地示例证明无需修改框架即可接入不同网站逻辑。20 个任务中模拟 3 个失败，总任务仍为 20，不生成补跑任务；另一网站启动被服务端拒绝。重启后资源、脚本及已保存结果可读取。
完成子任务的失败场景、旧数据迁移回归、实际浏览器交互检查；运行 `uv run pytest`、`uv run ruff check` 和 `git diff --check`。真实网站与邮箱/代理实测单独记录，不能用模拟结果代替。
