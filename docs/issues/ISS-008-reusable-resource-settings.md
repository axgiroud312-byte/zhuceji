# ISS-008：在设置中保存并复用邮箱资源和动态代理池

## 目标与范围

把邮箱与动态代理作为独立前置资源管理。用户在设置中配置、导入和检查，主页只查看摘要并选择本次资源；换网站无需重新输入同一份配置。首版沿用此前 Agnes 实际使用的邮箱与动态代理接入，不扩展所有邮箱供应商。

## 必要设计与依据

- 调查 `mailbox.py`、`users.py`、`proxy.py`、配置和原有调用路径，核实此前实际邮箱协议与代理来源。代码支持 Outlook/Graph/IMAP 不代表用户此前必然使用某一协议；调查记录不得包含真实凭证。
- 设置中保存命名资源及连接配置，提供检查状态和明确错误；主页可显示可用数量或供应方式、健康摘要，未知状态不能假称可用。
- 资源由任务绑定并经框架传给脚本。邮箱不足、凭证失效、代理不可用时给出明确原因，不静默改用其他资源或直连。
- 明确邮箱领取、占用、释放、同网站重复使用和跨网站复用规则；保留原有已提交账号的关联，避免再次分配造成重复注册。
- 沿用现有动态代理会话/轮换能力，核对租约及进行中任务的 IP 绑定；配置变更不应偷偷改变正在运行的任务。
- 凭证沿用 Vault，设置重启可恢复，页面摘要和日志不暴露密码/令牌。

## 验收方法

保存邮箱和代理后重启，主页可选择；两个示例脚本可绑定同一资源配置。缺失、耗尽和连接失败有可观察的状态与原因；并发领取不重复占用同一邮箱；设置修改不改变已启动任务绑定。使用受控邮箱/代理响应测试，真实服务验证另行记录。
