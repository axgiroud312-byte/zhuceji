# ISS-011：提供现代、简单且日志清晰的脚本运行主页

## 目标与范围

主页围绕选资源、选网站脚本、填数量、运行、查看结果组织。资源详情在设置中维护，脚本提供导入/更新入口。移除流程编排主线，不迁入高级设置。

## 必要设计与依据

- 基于 `web_ui.py` 现有主题、表格与日志能力制作设计稿，覆盖空状态、资源就绪、运行中及失败场景；先供用户查看，再落实界面。
- 讨论中的布局方向：上方紧凑资源摘要/选择和脚本选择，数量与启动/停止集中；中间任务结果列表为视觉重点；底部日志按需展开。具体排版不视为已验收。
- 现代化体现在主次清楚、状态易辨、操作短，不堆卡片或教程文案。缺资源时提供直达设置入口；资源选择受脚本声明约束。
- 任务行显示稳定标识、状态、当前阶段和失败摘要；点击查看该任务日志与脚本结果。支持按脚本字段展示，避免 API Key 固定列。
- 日志具备时间、任务标识、阶段/级别和可读消息；全局日志与单任务日志关联，技术详情按需展开。用户查看历史行时不被强制滚回底部，刷新不丢任务选择和过滤上下文。
- 日志由运行事件驱动，而非解析随意拼接的文本。分页/增量读取避免长时间运行拖慢主页；默认不暴露敏感字段。
- 网站运行期间控制项反映后端互斥状态。历史查询与当前运行不能混淆，脚本更新不改变当前任务版本。
- 同步替换依赖旧流程节点的 UI 测试，不为保留旧 DOM 而保留错误产品入口。

## 验收方法

在真实浏览器完成从设置资源、导入脚本到运行/日志/导出的路径，用户无需配置注册步骤。检查无资源、无脚本、失败和运行锁状态；并发任务日志能按任务独立追踪，长消息和大量日志不挤压主表。1440/768/360px 下主要操作可用，深浅主题文字可读；宽结果表可局部滚动、页面不横向溢出。记录截图及用户视觉反馈，设计稿不能代替真实交互验收。
