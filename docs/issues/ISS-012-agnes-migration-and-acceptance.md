# ISS-012：将 Agnes 接入通用脚本框架并保留旧数据完成闭环验证

## 目标与范围

让现有 Agnes 能力成为一个网站适配脚本，验证新框架真实贯通，而不是仅有演示页面。保留旧账号、凭证、代理配置、批次与结果的可读性，不改写外部生产隔离归档。

## 必要设计与依据

- 将 `agnes.py` 的网站专属注册/结果提取逻辑适配到 ISS-007；框架不能继续依赖 Agnes 特有选择器、验证码规则或 API Key 字段。
- 核对旧配置、SQLite 结构与 Vault 引用，设计可备份、可重复执行的迁移；失败时不损坏原数据。旧自定义流程先保留原始资料，说明其兼容范围，不默认全部可转换，也不恢复可视化编辑器。
- 旧任务映射到明确网站和结果字段；旧已提交任务不因升级进入新注册队列。
- 用第二个无真实外部请求的脚本验证网站无关性，防止框架只支持改名后的 Agnes。
- 更新 README、操作说明和状态规则，写清资源设置、脚本导入/更新、固定数量任务、单网站运行、日志和结果导出；移除将流程编排作为当前入口的说明。
- 真实服务实测需独立记录使用范围与结果，日志/截图/仓库不保存真实凭证。

## 验收方法

在包含虚构旧账号、凭证引用、代理和结果的数据库副本上迁移，核对前后数量/关联及结果可读性；重复迁移不重复创建数据，模拟迁移失败可恢复。以受控站点/邮箱/代理完整验证 Agnes 脚本；另一示例输出不同结果字段，两者无需修改框架即可依次运行。
运行固定数量失败场景、双标签页互斥、中断恢复、脚本更新、敏感结果导出及浏览器交互回归。执行 `uv run pytest`、`uv run ruff check`、`git diff --check`，报告实际通过与未验证范围；旧 Issue 的测试数字不能沿用为本轮结果。
