# ISS-003：实现批量账号智能导入预览向导与多模式账号登录/邮箱核验工作流

## 目标与范围

### 当前问题
1. 传统导入方式是“盲导”——用户把几百行文本粘进去点导入，导入前不知道分隔符对不对、哪几行缺了字段、密码被分到了邮箱密码还是平台密码列。
2. 用户既有“导入新邮箱去注册”的需求，又有“导入一批已经注册好的账号，去批量验证能不能正常登录并把 API Key 提出来”的需求，还需要方便地区分和验证邮箱收码连通性。

### 期望行为
1. **实时分列解析预览向导（Live Parse Preview Wizard）**：
   - 支持直接粘贴多行文本，或拖拽 `.txt` / `.csv` 文件到上传区。
   - 当用户粘贴文本或切换分隔符/密码用途时，下方**立刻实时生成“解析预览表格”**（显示总行数、有效行数、格式异常行数，以及前 20 行的分列结果：`邮箱`、`邮箱密码`、`平台登录密码`、`OAuth ClientID`、`RefreshToken`、`自动识别类型`），格式有误的行直接用红色徽章标出具体原因（如“第 5 行：未识别到有效邮箱地址”）。
2. **一键选择账号执行模式（新账号注册 vs 已有账号登录核验）**：
   - 用途卡片二选一：
     - **模式 A：🆕 新账号批量注册**（导入后状态为 `PENDING`，执行时走注册 ➔ 验证码 ➔ 拿结果流程）。
     - **模式 B：🔐 已有账号批量验证登录 & 提取结果**（导入后状态直接设为 `PENDING_VERIFY` / `REGISTRATION_SUBMITTED`，执行时跳过注册，直接打开登录页验号并提取 API Key / 目标结果）。
3. **直观的验证方式配置面板**：
   - 卡片化切换**注册验证码方式**（`自动邮箱 Graph/IMAP 收码`、`弹出浏览器人工填码`、`免验证码直提`）与**账号登录核验标准**（`严格匹配页面邮箱 + 已登录标志`、`仅检查已登录元素`、`跳出登录页 + LocalStorage Token`）。
   - 支持对已导入账号执行单条或批量「验证登录 & 拿结果」以及「测试邮箱收信连接」。

### 本次包含与排除的内容
- **包含**：拖拽/粘贴导入区、实时分列解析预览表与异常行高亮、新注册/已有账号模式选择、自动创建或追加到指定批次、验证码与登录核验模式切换卡片。
- **排除**：对接第三方付费打码平台 API（当前聚焦邮箱 OAuth/IMAP 自动接码、人工验证码及免验证码模式）。

## 必要设计与依据

- **交互设计参考**：
  - 参考 **Supabase / Retool / 现代 SaaS CSV 导入向导**：输入区与实时预览表上下联动，用户输入即预览（零网络延迟前端实时解析 + 后端严格入库校验双重保障）。
- **后端支撑依据（`src/agnes_provisioner/users.py` & `src/agnes_provisioner/mailbox.py`）**：
  - `import_accounts_flexible` 支持自动识别 5 段式、4 段式（`邮箱----邮箱密码----client_id----refresh_token`）、3 段式（`邮箱----邮箱密码----平台密码`）、2 段式（`邮箱----密码`）、1 段式纯邮箱与标准 CSV。
  - 重复邮箱自动更新加密凭证库（`Vault`）中的令牌与密码，不因重复记录中断整批导入。

## 验收方法

1. **实时解析预览验证**：
   - 在导入框粘贴混合了四段式、两段式和 1 行错误格式的文本，观察下方预览表是否无需点击提交即实时展示正确的分列结果，并将错误行标红提示行号与原因。
2. **已有账号直接验号模式验证**：
   - 选择“🔐 已有平台账号（直接登录验证 & 提取结果）”，填入批次名 `verify-only-batch` 并点击导入；跳转到任务大盘后，确认这批任务处于 `等待验证 (PENDING_VERIFY)` 且阶段为 `REGISTRATION_SUBMITTED`，点击运行或批量验证时直接走 `reconcile` 登录流程而非注册流程。
3. **验证方式切换检查**：
   - 切换验证码方式为“人工手动输入验证码”并保存，检查 `headless` 是否自动联动切换为 `false`（显示浏览器窗口）。
